# Independent Implementation Plan Review

Required final review prompt for loom_plan_reviewer. Review the complete planning
manifest, indexed domain cards (or legacy planning.md), implementation manifest,
and all linked phase cards as one packet. The reviewer must not be its author.
For implementation startup, review only the manager's named missing evidence or
source/contract drift and affected owners; reuse unaffected passed readiness.

Read AGENTS.md, the planning workflow, exact assigned artifact paths/headings,
and source/tests needed to verify material claims. Check:

- current necessity, adjacent capability reuse, and removable complexity;
- behavior, examples, public/durable/trust/provenance contracts and failure paths;
- unique ID ownership and complete planning-to-phase/shared/deferral traceability;
- one-to-one manifest/card consistency and acyclic dependencies;
- independently acceptable phase results, cohesion, supported merge states,
  explicit ownership/exclusions, and discriminating acceptance checks;
- fixed contracts versus private discretion and finite execution matrices;
- invariant ownership, affected consumers, required dependency/physical lanes,
  proportional validation, and preservation of approved obligations;
- domain neutrality, imports, durability, compatibility, risks, and stop conditions.

Lead with classified findings. A blocker needs a reachable supported path,
accepted contract/invariant, material consequence, evidence, and smallest remedy.
Separate required corrections from optional hardening or future capability.
Review cannot add acceptance criteria. Report the reviewed packet revision/tree
and paths, source assumptions, readiness result, and residual risks.

Do not edit, create a report sidecar, or request a new full review loop. The
manager records the receipt at the implementation manifest's readiness owner.
A qualifying reusable process weakness may be returned as a concise candidate
for `$loom-process-improvement`; it does not become a product requirement.
